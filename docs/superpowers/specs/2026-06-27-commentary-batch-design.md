# 学生评教界面统一与分类级一键评教设计

## 1. 背景

当前学生评教功能位于 `lib/pages/Commentary/`，整体仍然使用较早的 `Scaffold + AppBar + Card/ListView` 结构。相比首页功能区、考试安排、课表等已经完成统一主题化的页面，评教页在以下方面明显不一致：

- 缺少统一的玻璃背景和浮层卡片语言
- 缺少总览信息与页面层级，进入后只有朴素列表
- “理论课 / 实验课”分类只是列表项，不具备清晰的主操作
- 当前“一键完成”仅存在于单门课程题目页，不能对整类课程直接批量完成

用户目标有两部分：

- 让学生评教页面视觉上和当前主体 UI 统一
- 在“理论课 / 实验课”分类层级提供按钮，点击后直接把该分类下所有未评课程自动评教完成

## 2. 目标与非目标

### 2.1 目标

- 将学生评教首页、课程列表页、题目页统一到当前应用的玻璃卡片视觉体系
- 在评教批次首页为每个分类卡片提供“一键评完”操作
- 一键评完时直接批量提交该分类下所有未评课程，不要求用户逐门进入
- 复用现有评教接口和自动选项策略，不引入新的后端依赖
- 在批量处理中提供明确状态、进度、成功失败汇总和防重复触发保护
- 保持现有单门进入题目页、手动提交、一键完成的能力不回退

### 2.2 非目标

- 不改动教务系统接口协议
- 不调整现有自动评分策略
- 不引入复杂任务队列、后台任务恢复或离线补偿
- 不对评教业务规则做自定义打分配置

## 3. 现状与事实依据

### 3.1 现有页面

- `lib/pages/Commentary/commentary_batch_page.dart`
  负责加载评教批次列表，当前仅支持点进分类课程列表
- `lib/pages/Commentary/commentary_course_list_page.dart`
  负责加载某个分类下的课程，支持单门进入题目页
- `lib/pages/Commentary/commentary_question_page.dart`
  负责加载单门评教题目，当前已支持单门“一键完成”和手动提交

### 3.2 现有接口

- `getCommentaryBatches()`
  获取批次首页数据
- `getCommentaryList(pj01id, batchId, pj05id)`
  获取某个分类下课程列表
- `getCommentaryQuestions(batchId, evaluationCategoriesId, courseId, teacherId, noticeId)`
  获取某门课程的题目与选项
- `submitCommentary(...)`
  提交某门课程的评教答案

### 3.3 现有自动评教规则

当前单门题目页已经存在 `_buildAutoSelections()`：

- 第一题选择分值 `< 4.75` 的选项
- 其余题目选择分值 `>= 4.75` 的选项

本次批量评教将严格复用该逻辑，保证单门一键完成与分类级一键评完行为一致。

## 4. 设计原则

- 本地最小改造，沿用已有主题、玻璃组件和提示组件
- 主操作前置，把“一键评完”放在分类卡片上，而不是埋到二级页
- 批量流程透明，用户始终知道当前是否在运行、跑到哪一门、成功多少、失败多少
- 异常可恢复，单门失败不应阻断整个分类的后续课程
- 不破坏已有单门评教路径，保留手动兜底能力

## 5. 方案对比

### 5.1 方案 A：批次首页分类卡片直接一键评完

做法：

- 在批次首页把“理论课 / 实验课”渲染成高信息密度卡片
- 每张卡片同时提供“查看课程”和“一键评完”
- 点击“一键评完”后，在当前页直接跑完整个分类的批量提交

优点：

- 最符合用户预期，入口直接
- 与分类信息强绑定，用户理解成本最低
- 最容易把视觉结构做成和主体功能页一致

缺点：

- 首页需要承担更多状态管理和进度展示

### 5.2 方案 B：列表页顶部一键评完本分类

做法：

- 首页只保留进入分类
- 在课程列表页头部放“一键评完本分类”

优点：

- 改动相对集中

缺点：

- 用户必须多点一步才到主操作
- 不符合“理论课、实验课这里弄一个按钮”的明确要求

### 5.3 方案 C：首页按钮只负责跳转并自动开始

优点：

- 技术上能复用列表页逻辑

缺点：

- 交互割裂，用户看到按钮但并非原地完成
- 容易让人误以为按钮没有立即生效

### 5.4 结论

采用方案 A。

## 6. 页面与交互设计

### 6.1 学生评教首页

目标：将 `commentary_batch_page.dart` 从朴素列表升级为和 `ExamSchedulePage`、`FunctionPage` 同一视觉体系的功能首页。

页面结构：

- 玻璃背景：使用 `AppGlassBackground`，延续主应用已有柔和底色与浮层感
- 顶部返回按钮：复用当前应用页面内返回按钮风格
- 总览卡：
  - 标题：`学生评教`
  - 副标题：说明支持分类级一键完成
  - 指标：分类数量、未评课程总数
  - 提示：自动按系统默认高分选项提交
- 分类区：
  - 每个分类渲染为一张玻璃卡片
  - 显示批次名、分类名、学期、未评数/总数
  - 提供两个动作按钮：
    - `查看课程`
    - `一键评完`

状态表现：

- 正常态：展示分类信息与操作按钮
- 加载态：使用统一加载面板，而不是空白转圈
- 批量进行中：
  - 当前正在执行的分类卡片进入忙碌态
  - “一键评完”按钮禁用并展示进度，如 `3 / 8`
  - 其它分类按钮也禁用，避免并发批量提交
- 空态：展示“当前暂无可评教批次”
- 错误态：展示友好的错误面板和重试入口

### 6.2 课程列表页

目标：统一视觉风格，并作为批量结果核对与手动兜底页。

页面结构：

- 同样使用玻璃背景
- 顶部展示分类摘要卡：
  - 分类名
  - 未评数 / 已评数 / 总数
  - 提供次级按钮 `一键评完本分类`
- 下方课程卡片列表：
  - 课程名
  - 课程编号
  - 教师名
  - 状态标签：`未评教` / `已评教`

交互规则：

- 未评教课程可点击进入题目页
- 已评教课程点击后继续提示“已经评教过啦~不能重复评教”
- 若列表页进行分类级一键评完，其状态和首页规则一致，但优先级低于首页入口

### 6.3 题目页

目标：不改变原有功能边界，只统一视觉表达。

页面结构：

- 玻璃背景
- 顶部操作保留：
  - `一键完成`
- 题目区域使用更清晰的卡片分组
- 底部主提交按钮保留

交互规则：

- 手动选择全部题目后可提交
- 一键完成继续复用当前自动选项规则
- 提交中禁用按钮，避免重复发起

## 7. 批量评教流程设计

### 7.1 总体流程

针对某个分类卡片点击“一键评完”后：

1. 拉取该分类课程列表
2. 过滤出 `isSubmitCode != '1'` 的未评课程
3. 若未评课程为空：
   - 直接提示“该分类已全部评教完成”
   - 刷新首页统计
4. 对每门未评课程按顺序执行：
   - 拉取该门课程题目
   - 使用现有自动选项规则构造答案
   - 调用提交通道提交
5. 记录每门课程结果：成功 / 失败 / 失败原因类型
6. 执行完后刷新分类列表与统计信息
7. 给出汇总提示

### 7.2 为什么采用串行而不是并行

- 教务接口稳定性和限流行为未知，并发提交风险更高
- 串行更容易展示清晰进度和定位失败课程
- 当前用户诉求是“直接评完”，不是极限压缩执行时间

因此本次明确采用串行处理。

### 7.3 自动选项构造规则

批量流程复用单门题目页现有逻辑：

- 首题选 `< 4.75`
- 其余题选 `>= 4.75`
- 若某题没有符合条件的选项，则该门课程判定为失败，不提交该门

### 7.4 失败策略

单门失败不终止整个分类批量流程。

失败场景包括：

- 拉题目失败
- 某题无法匹配自动选项
- 提交接口异常
- 提交结果不是 `success`

结束后汇总反馈：

- 全部成功：`已完成 X 门课程评教`
- 部分成功：`成功 X 门，失败 Y 门，可进入课程列表继续处理`
- 全部失败：`本次未完成任何课程评教，请稍后重试`

## 8. 状态管理与组件边界

### 8.1 首页需要新增的状态

- 批次列表 Future
- 每个分类的统计信息
- 当前是否存在批量任务
- 当前批量任务所属分类 ID
- 当前进度：已处理数 / 总数
- 当前批量结果摘要

### 8.2 推荐的职责拆分

- `commentary_batch_page.dart`
  负责页面壳、总览、分类卡片、批量任务入口与刷新
- 可新增评教批量辅助逻辑
  - 例如 `commentary_batch_executor.dart`
  - 负责“课程列表获取 → 题目获取 → 自动选项构造 → 提交 → 汇总”
- `commentary_question_page.dart`
  抽出自动选项构造逻辑供批量流程复用，避免复制两套评分策略

### 8.3 接口复用策略

为避免 UI 组件直接串联底层批量细节，批量执行逻辑应封装成清晰接口，例如：

- 输入：分类标识与依赖的拉取/提交函数
- 输出：总数、成功数、失败数、失败课程摘要

这样既便于页面调用，也便于 widget / unit test 替换依赖。

## 9. 错误处理与用户反馈

反馈组件继续使用 `showAppSnackBar`，类型保持和现有页面一致。

需要覆盖的反馈：

- 首页列表打开失败
- 批量任务已在运行中，忽略重复点击
- 当前分类没有未评课程
- 题目仍在加载或数据异常
- 分类批量完成 / 部分完成 / 全部失败

为展示更稳定的处理中感知，分类卡片内应提供轻量进度说明，而不是反复弹 SnackBar。

## 10. 测试设计

### 10.1 首页批量评教测试

需要新增覆盖：

- 点击“一键评完”后，只发起一次批量任务，重复点击被忽略
- 当分类下课程全部已评时，直接提示完成，不触发提交
- 批量过程中能按顺序处理多门课程
- 单门失败不会阻断后续课程
- 批量结束后刷新首页状态
- 批量成功、部分成功、全部失败三种汇总提示正确

### 10.2 列表页测试

需要新增或补强：

- 顶部摘要信息渲染正确
- 列表页一键评完入口状态正确
- 单门评教返回成功后列表刷新
- 已评教课程仍不可重复进入

### 10.3 题目页测试

需要确认：

- 自动选项规则抽取后，单门一键完成行为不变
- 手动提交、提交中禁用、异常提示不回退

### 10.4 验证命令

- `flutter test test/pages/commentary`
- `flutter analyze`

## 11. 风险与边界

- 教务接口返回字段可能存在不完整数据，批量流程必须容忍单门失败
- 自动评分规则是经验规则而非配置化规则，本次只复用现状，不对其正确性做业务扩展
- 如果分类内课程很多，串行执行会有一定等待时间，因此必须给明确进度
- 批量完成后列表刷新依赖接口返回最新状态，若教务系统状态更新有延迟，页面提示需避免绝对化措辞

## 12. 成功标准

满足以下条件视为本次需求完成：

- 学生评教首页视觉与现有主体页面统一，不再是旧式普通列表
- “理论课 / 实验课”卡片上存在直接可见的“一键评完”按钮
- 点击后能直接完成该分类下所有未评课程的自动评教
- 批量过程中有防重复点击、进度反馈和结果汇总
- 单门评教流程保持可用
- 新增测试覆盖批量主流程，且 `flutter analyze` 通过
