# 成绩与课表学期选择设计

## 背景与目标

成绩页当前会在并发探测前仅保留 `-1` 与 `-2` 学期，导致教务系统返回的 `-3` 等学期不会出现在可选成绩列表中。本次移除这项预过滤，但保留已上线的缓存恢复、后台刷新、并发探测、空结果剔除和失败保留行为。

课表页当前只能抓取当前学期。新版教务系统已提供学期列表和按学期抓取普通课表的协议，本次让用户在手动抓取前选择任一教务系统返回的学期，并同时抓取普通和实验课表。

## 已确认的教务协议

所有请求均为登录后的 `POST` 请求，基址为 `https://jwxtsj.hut.edu.cn`。

| 用途 | 路径 | 关键数据 |
| --- | --- | --- |
| 可选学期 | `/njwhd/getXnxqList` | 数组元素包含 `xnxq01id`、`xqmc`、`isdqxq`；不筛除 `-3` |
| 节次模式 | `/njwhd/Get_sjkbms` | 返回默认节次模式的 `kbjcmsid` |
| 普通课表 | `/njwhd/student/curriculum?xnxq01id=<id>&kbjcmsid=<id>&week=<week>` | 逐周请求 |
| 实验课表 | `/njwhd/teacher/courseScheduleExp?xnxq01id=<id>&week=<week>` | 逐周请求 |

已验证 `week=all` 的普通课表响应不带实际日期，不能喂给现有按日期存储与展示的课表解析器。因此普通课表必须继续逐周抓取，复用现有日期解析、并发、重试和进度机制。

认证 Token、Cookie、账号和密码均不进入日志、测试样本或文档。

## 方案选择

采用“逐周并发抓取”方案：

1. 读取学期列表和默认节次模式。
2. 由用户选择学期后，普通课表逐周请求携带所选 `xnxq01id` 与 `kbjcmsid`。
3. 实验课表逐周请求携带同一 `xnxq01id`。
4. 两条抓取链路继续并发执行，并复用全局请求并发上限、失败重试和同步进度。

不采用 `week=all` 单次请求，因为其缺少日期；不新增周次视图或人为推算日期，因为这会扩大数据模型与 UI 范围且没有可靠的学期首日数据来源。

## 课表交互与数据流

1. 用户点击已有的“从教务系统抓取课表”入口。
2. 应用取得 `getXnxqList` 返回的所有有效学期，并展示学期选择底部弹窗。
3. 当前学期（`isdqxq == '1'`）默认选中且显示“当前”标识；`-1`、`-2`、`-3` 等返回项均可选。
4. 用户确认后才启动同步；关闭弹窗或未确认不发送课表抓取请求。
5. 同步先取得默认 `kbjcmsid`，再并发抓取普通课表和实验课表，展示现有进度与错误状态并防止重复发起。
6. 合并两类课程，沿用当前保存与小组件刷新流程。

## 保存与覆盖规则

- 重新抓取仅覆盖“当前登录账号 + 教务系统抓取来源 + 所选学期”完全相同的本地课表。
- 覆盖后将该课表设为活动课表。
- 其他学期、其他账号、手工创建或导入的课表均不得被覆盖。
- 课程数据为空时沿用现有失败提示，不创建空课表。

## 成绩查询调整

- 删除只允许 `-1`、`-2` 学期进入探测管线的判断及其专用测试辅助逻辑。
- 教务系统返回的全部有效学期 ID 都进入现有分批并发探测。
- 成功且成绩非空：保留；成功但成绩为空：剔除；网络异常重试耗尽或业务错误：保留。
- 缓存读取、缓存写入、已选学期恢复、全部成绩初始加载和后台刷新行为保持不变。

## 错误处理

- 学期列表或节次模式加载失败时，不开始同步并显示可理解的失败信息。
- 普通或实验课表任一必要请求在重试后仍失败，沿用当前同步失败语义，避免保存不完整课表。
- 同步期间重复操作继续被拦截；用户离开页面时沿用现有取消与 mounted 检查。

## 验收与测试

1. 成绩探测将有成绩的 `2025-2026-3` 保留，将空结果的同类学期剔除。
2. 成绩请求错误或业务错误时，任意学期 ID 均按现有规则保留。
3. 学期选择器展示 `getXnxqList` 的全部有效学期，默认选择当前学期；关闭后不触发同步。
4. 选择历史学期后，普通课表逐周请求带有所选 `xnxq01id` 与 `kbjcmsid`，实验课表逐周请求带有相同 `xnxq01id`。
5. 相同账号、相同学期、教务抓取来源的课表被覆盖并设为活动；其他课表不变。
6. 运行相关单元/组件测试及 `flutter analyze`。

## 范围外

- 不修改教务系统远端数据。
- 不改动手工创建、导入、导出和分享课表的协议。
- 不改造成 `week=all` 单次抓取，也不新增周次视图。
