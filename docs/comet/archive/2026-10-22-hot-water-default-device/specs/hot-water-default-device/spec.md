# 宿舍热水默认设备

## Outcome

宿舍热水页面支持「固定默认设备」：设备较多的用户可以把某一台设备显式设为默认，之后每次打开页面都自动选中这台设备，当前设备卡片上标注「默认」；默认设备被删除或已被学校侧解绑时，页面回退到列表第一台设备且不残留旧运行态。

## Requirements

### R1 默认设备存储

- 默认设备以设备号（`poscode`，String）标识，保存在 SharedPreferences 中，应用重启后仍生效。
- 存储键使用独立命名（如 `hot_water_default_device`），不与饮水页的 `device_note_*`、`device_order` 等键冲突。
- 默认设备存储通过可注入的抽象暴露（读 / 写 / 清除），默认实现走 SharedPreferences；逻辑层不直接触碰偏好 API，便于测试替换。
- 读取失败（偏好不可用）按「无默认设备」处理，不抛出、不阻塞页面加载。
- 写入失败给出用户可读提示，不静默丢弃。

### R2 加载时按默认设备选中

- 设备列表加载完成后，若本机保存的默认设备号存在于返回列表中，页面选中该设备。
- 若不存在默认设备，或默认设备号不在返回列表中（已被解绑），选中列表第一台设备。
- 设备列表为空时不选中任何设备（`choiceDevice` 保持 `-1`）。
- 默认设备的解析只依据设备号，不依赖列表下标；设备列表顺序变化不影响默认设备的选中结果。

### R3 显式设为默认与取消默认

- 「选择设备」列表的每一行提供独立的默认标记入口（星标）。
- 点击星标把该设备设为默认：默认标记转移到该行，页面立即反映；该操作不改变本次会话的当前选中设备，也不关闭列表。
- 再次点击已是默认的设备的星标取消默认：默认标记被清除，回到「无默认设备」状态。
- 点行仍然是「本次选择该设备」的行为（选中并关闭列表），不写入也不清除默认设备——默认设备只能由星标显式变更。
- 默认标记在「选择设备」列表和「当前设备」卡片上均可见：当前选中的设备恰好是默认设备时，卡片显示「默认」标记。

### R4 与「设备未关闭」状态的优先级

- 检测到有设备尚未关闭时，仍然优先选中该未关闭设备并给出既有提示，不被默认设备覆盖。
- 未关闭设备优先级高于默认设备时，卡片的「默认」标记按当前实际选中的设备判断（此时不是默认设备，不显示该标记）。

### R5 设备删除后的清理

- 删除设备成功后，若被删设备正是默认设备，则清除本机默认偏好。
- 清除后重新进入页面选中列表第一台设备。
- 删除设备失败时保持既有行为（弹层保持打开、可重试），不触碰默认偏好。

### R6 持久化时机与一致性

- 设为默认 / 取消默认的写入在本机立即生效，退出页面再进入仍保持。
- 页面关闭后返回的迟到的设备列表或默认设备读取结果不得写入状态。
- 默认设备读取不影响设备状态检查与余额刷新，三者仍并发进行。

## Scenario

- Scenario: 设备列表加载后，本机保存的默认设备号在返回列表中时，页面自动选中该设备，且当前设备卡片标注「默认」。
- Scenario: 本机没有保存过默认设备时，保持现状选中列表第一台设备。
- Scenario: 在选择设备列表中点击某台设备的「设为默认」后，该选择被持久保存，退出并重新进入宿舍热水页面仍自动选中它。
- Scenario: 在选择设备列表中再次点击已设为默认的设备可取消默认；取消后重新进入页面回到选中列表第一台。
- Scenario: 检测到有设备未关闭时，仍优先选中该未关闭设备并给出提示，不被默认设备覆盖。
- Scenario: 删除已设为默认的设备后，本机默认偏好被清理，重新进入页面选中列表第一台，且不报错、不残留旧运行态。
- Scenario: 默认设备已被学校侧解绑（不在返回列表中）时，回退选中列表第一台，不崩溃、不残留旧运行态。
