# 课程班级显示

## Outcome

课程详情弹层（`CourseDetailSheet`）在既有信息行（周数、时间、教师、班级、地点）基础上展示教务系统返回的课程元信息：班级串、上课人数、学时、考核方式。数据来自教务系统普通课表与实验课表接口的对应字段，随课程数据一起解析、持久化、复制与分享。

详情弹层的信息行采用「字段名标签 + 值」的统一形态：每个字段都有明确的中文标签，不再只显示裸值；数值型字段追加单位（上课人数为「人」、学时为「学时」）。信息行整体收紧（行高由约 66px 降至约 48px），使弹层可视高度内可容纳更多信息。

## Requirements

### R1 课程数据模型携带课程元信息

- `Course` 拥有 `className`（班级串，String，默认空串）。
- `Course` 拥有 `peopleCount`（上课人数，String，默认空串）、`creditHours`（学时，String，默认空串）、`assessmentType`（考核方式，String，默认空串）。三者统一用 String 承载，解析时把接口的数字值规范为字符串。
- `toJson` 包含上述四个字段；`fromJson` 读取这些字段，缺失时回退空串（兼容旧本地数据、旧分享码、旧导出文件）。
- `sanitizedForShare` 保留上述四个字段，继续剥离 `pcid`。
- `_isSameCourse` 比较不包含这些字段（避免同课程因班级/人数显示差异被判定为不同课程条目）。

### R2 同步解析

- 普通课表解析（`GetSingleWeekClass.getSingleClass`）从每条 item 读取：`ktmc` → 班级串、`peopleNumber` → 上课人数、`zxs` → 学时、`khfs` → 考核方式。
- 实验课表解析（`GetSingleWeekExpClass.getSingleClass`）从每条 course 项读取：`ktmc` → 班级串、`peopleNumber` → 上课人数。
- 班级串取值：实验课的 `ktmc` 可能形如「班级 + 课程号 + 组号」。当 `ktmc` 以该条目的 `kch`（课程号）开头时，截断到 `kch` 之前的部分作为班级串；否则原样保留。
- 班级串与其它元信息的取值都做 trim：字段缺失、为 null 或仅含空白时写空串，不写入空白内容。
- 班级串中的合班逗号串（如「土木工程2307班,智能建造[2303-2304]班」）原样保留，不解析、不拆分、不排序、不改写。

### R3 详情弹层显示

- 详情信息列表含「班级」行（位于「教师」行之后）与「上课人数」「学时」「考核方式」三行，连同「周数」「时间」「教师」「地点」，共 8 行。
- 每行都由三段组成：图标、字段名标签、字段值。8 行都必须有字段名标签，不允许出现「只有图标 + 裸值」的行。
- 字段名标签固定为：周数、时间、教师、班级、上课人数、学时、考核方式、地点。
- 标签列宽度固定，值列左对齐成整齐一列；标签使用弱化色，值使用主色。
- 数值型字段在值后追加单位：「上课人数」为「人」，「学时」为「学时」。其余字段不追加单位。
- 只有当字段值为纯数字时才追加单位；非数字值原样显示，不拼接单位。
- 空值时保留字段名标签，值位置显示弱化的「暂无」文案（不显示空白，也不重复完整回退句）。
- 班级等长文本允许自动换行完整显示（不参与现有单行缩放逻辑），超长文本不截断。
- 长按某行复制该行的「字段名：值」形式文本，提示与现有信息行一致。
- 课表格子卡片内不显示这些信息。

### R4 详情弹层行距

- 详情行的行高从约 66px 收紧到约 48px：行内边距由 14 降为 8，图标容器由 38×38 降为 32×32，图标尺寸由 19 降为 17。
- 收紧后 8 个详情行的合计高度约 384px（改动前约 528px）。
- 详情行与操作行共用同一行组件，收紧对两者一致生效。

### R5 复制文本包含课程元信息

- 「复制课程信息为文本」的输出在既有行之后依次增加「上课人数」「学时」「考核方式」三行。
- 「上课人数」「学时」两行在值为纯数字时追加单位（分别为「人」「学时」）。
- 复制文本保留各行原有的「暂无…」完整回退文案（该文本没有相邻标签，不使用简写「暂无」）。

### R6 分享码携带课程元信息

课表分享码的课程数据包含上述四个字段；旧版本应用导入含新字段的分享码不报错（按未知字段忽略），新版本导入后详情弹层与复制文本显示这些信息。

### R7 已有本地课表的刷新

- 升级到含这些信息的版本后，本地已存在的课表（缓存中无这些字段）不因本变更被破坏或清空。
- 用户在 App 内重新执行一次课表同步后，新同步到的课程条目携带班级串与元信息。

## Scenario

- Scenario: 同步后打开带有班级数据的课程详情，详情信息列表的 8 行各自显示字段名标签（周数、时间、教师、班级、上课人数、学时、考核方式、地点），内容与教务返回一致，长文本自动换行完整显示，长按可复制。
- Scenario: 实验课条目的班级行显示剥离课程号后缀后的纯班级串（如「智能建造2304班」）；实验课班级为纯班级串时（如「智能建造[2303-2304]班」）原样显示。
- Scenario: 打开旧课表数据（无这些字段）的课程详情，班级与三行元信息各自显示弱化的「暂无」，其余信息行不受影响。
- Scenario: 打开有元信息的课程详情，「上课人数」显示为「30 人」，「学时」显示为「16 学时」，「考核方式」显示为「考试」；实验课的「上课人数」等于其分组人数并同样带「人」单位。
- Scenario: 「上课人数」「学时」「考核方式」任一缺失或为空时，对应行保留字段名标签、值显示「暂无」，其余行不受影响。
- Scenario: 详情行比改动前更紧凑——8 行总高约 384px，明显低于改动前的约 528px。
- Scenario: 长按「上课人数」行复制的内容为「上课人数：30 人」，长按「学时」行为「学时：16 学时」。
- Scenario: 「复制课程信息为文本」的结果在既有行之后包含「上课人数：30 人」「学时：16 学时」「考核方式：考试」三行，空值时写各自完整回退文案。
- Scenario: 带这些字段的课表生成分享码，旧版本应用导入该分享码不报错（未知字段被忽略）；旧分享码导入新版本，缺失字段显示「暂无」。
- Scenario: 升级后未重新同步的本地课表仍可正常打开，相关行显示「暂无」；用户重新同步一次后，相关行显示真实值。
