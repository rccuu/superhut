# 惠生活798（校园饮水设备）

## 目的

让 superhut 内的「慧生活798」功能可用：登录惠生活798账号、查看与管理已收藏的饮水设备、启动接水并自动结算。本能力与官方客户端行为对齐，界面采用浅色分层表面并保证文字可读性。

## 能力入口

- 功能页以「慧生活798」卡片进入，不需要教务系统凭据即可打开。
- 未登录（`hui798IsLogin` 为假）时进入 798 登录页；登录成功后回到饮水首页并加载设备列表。
- 饮水首页顶部为透明 AppBar 与 `extendBodyBehindAppBar`，标题为「慧生活798」，背景保留共享的环境气泡层并受整机轻量模式门控。

## 请求头与超时

- 798 的每个请求携带且仅携带两个自定义头：`VersionCode: 3.1.8`、`User-Agent: Android_ilife798_3.1.8`。
- 不发送 `ApplicationType`、`Accept`、`Accept-Encoding`、`Connection`。
- 不发送 `sign` 查询参数——服务端不校验签名，带上签名反而被拒。
- 连接超时与接收超时均为 15 秒。
- 基址为 `https://i.ilife798.com/api/v1`。

## 凭据与登录态

- Token 及账号标识以 JSON 保存在 `drink798UsrApiToken`，登录标记保存在 `hui798IsLogin`。
- 任何需要鉴权的请求都在本地 Token 读取完成之后才发出；冷启动后第一次鉴权请求携带的是已保存的 Token，而不是空值。
- 本地保存的内容不是 JSON 对象时按未登录处理，并清掉该坏数据；此过程不抛异常，也不影响其他请求。
- 登录成功后写入新凭据前，先等待启动时的旧凭据读取结束，避免迟到的旧值覆盖新值。
- 服务端在设备列表中表明账号信息缺失时，清除登录标记、停止状态轮询并跳转登录页，且只跳转一次。

## 登录请求

- 获取图形验证码：`GET /captcha/`，参数 `s`、`r`，响应为字节流。
- 发送短信验证码：`POST /acc/login/code`，请求体为 `s`、`authCode`、`un`。
- 登录：`POST /acc/login`，请求体恰为 `openCode`（空串）、`authCode`、`un`，不含 `cid`。
- 发送短信与登录返回统一的失败描述，区分三种情形：
  - 服务端明确拒绝：返回服务端码与 `msg`，界面显示服务端 `msg`；
  - 服务端接受（`code == 0`）但响应缺少账号信息：提示「登录已被接受，但响应缺少账号信息」，不得显示成验证码错误；
  - 网络异常或响应无法解析：提示标题为「登录异常」并显示技术原因，提示展示 8 秒。
- 登录成功才保存凭据并置登录标记。

## 开始接水请求

- `GET /dev/start`，查询参数恰为 `did`、`upgrade=true`、`ptype=0`、`args=`（空串）、`rcp=false`、`cnt=1`；不发送 `stype`。
- `GET /dev/end`，查询参数为 `did`。
- `GET /dev/favo`，查询参数为 `did`、`remove`。
- `GET /ui/app/master` 取设备列表与收藏；`GET /ui/app/dev/status` 取设备状态（参数 `did`、`more=true`、`promo=false`，`gene.status == 99` 视为空闲）。

## 服务端返回透出

- 接水与结算的返回值携带服务端码与信息文案；`code == 0` 为成功。
- 失败提示的正文优先使用服务端 `msg`；`msg` 缺失时使用固定文案（开始为「设备无响应，请检查设备状态」，结算为「结算可能未成功，请检查」）。
- 服务端码 `-99` 表示登录态过期，提示为「登录已过期 / 请重新登录后再试」，并使用与一般失败不同的警示语义。
- 提示沿用应用统一的消息条原语：一般提示、成功、警示、错误四种语义各用其对应样式。

## 798 登录页

- 单一浅色表面：`Scaffold` 不设置背景色；页面只有一个渐变，即高度 168 的顶部品牌带，自品牌蓝不透明淡出到 alpha 为 0，其纯色等于主题 `scaffoldBackgroundColor`；不绘制卡片层，深浅模式下都不出现 `#0099CC` 的实色或渐变终止色。
- 头部为图标块 + 标题 + 副标题，文字取主题的 `onSurface` 与 `onSurfaceVariant`，两者必须不同。
- 手机号与图形验证码、短信验证码是同一页面内的两个面板：提交手机号后面板就地切换为短信码并保留已输入的手机号，面板内提供返回上一步的入口，返回时重新拉取图形验证码。没有独立的短信码路由页面。
- 图形验证码图片显示为 104×52，与验证码输入框在同一行且垂直中心相差小于 4 像素；点击图片即重新拉取，页面不设单独的刷新按钮。加载中显示占位槽而不显示图片。
- 验证码输入框使用数字键盘与仅数字过滤器，`maxLength` 为 6（不截断官方的 5 位码），居中显示。
- 手机号输入框使用电话键盘并限制长度。
- 输入框与主按钮使用应用共享的表单组件：输入框在正常、启用、聚焦三态圆角一致且不显示计数器文字；主按钮整行宽、加载态显示进度指示并拒绝重复点击。
- 空的手机号或验证码提交时给出提示且不发送请求；同一步的请求在途时重复点击不再发送第二次。

## 798 首页表面与配色

- 页面使用私有 token 表区分页面底、卡片、tint、顶部带与禁用态；浅色取值为页面底 `#E4EEF8`、卡片 `#FFFFFF`、tint `#DCEBF9`、顶部带 `#C5E0F7`、发丝线 `0x4D7E96AE`，深色取值为页面底 `#0A0F14`、卡片 `#1E2934`、选中 `#283645`、tint `#31404F`、顶部带 `#0D1A28`、发丝线 `0x594C6076`；强调渐变 `#0277BD`→`#00619E`。
- `Scaffold.backgroundColor` 等于页面底 token；背景是终止点不全等的命名渐变：空闲态为顶部带→插值色→页面底（终止于 `t = 1.0` 且与 `Scaffold.backgroundColor` 相同），接水态另用一层前景渐变，其最后一层终止色等于页面底。
- 卡片与页面底、tint 芯片与所依托表面之间相对亮度分离不低于 1.15:1，并同时有第二个可辨通道（描边或阴影）。
- 正文与次要文字在其真实背景上对比度不低于 4.5:1；两个标题不低于 3.0:1；着色芯片内的图标不低于 3.0:1。浅色的 `#00D4FF` 不作为强调渐变终止色。
- 主操作按钮由外层绘制渐变（可开始为强调渐变、可结算为警示色、不可用为禁用底色）与内层背景透明的 `FilledButton` 组成，并显式设置禁用底色以避开 Material 的遮罩回落；不可用时不响应点击、不调用接口。
- 页面文字层级只用固定的字号集合，标题靠字号与字重而非超高对比度突出。

## 设备选择与选中态

- 点击设备行即选中；选中行具有品牌色 1.6px 描边、勾选标记与抬升阴影，未选中行三者皆无。
- 移除色彩后（灰度）选中态仍可经至少两个通道区分。
- 选中行的最小高度不小于未选中行，编辑入口与操作按钮满足既有触控尺寸。

## 设备布局与排序

- 两种布局：单列列表与两列网格；切换后写入 `device_list_layout`，下次进入时恢复；排序模式下布局切换按钮禁用。
- 排序模式由页面入口进入/退出，使用带独立拖拽手柄的可重排列表，并在顶部显示提示条。
- 重排结果写入 `device_order`；再次加载时按以下规则恢复：已知名按保存顺序排前，未知名保持原有相对顺序追加，保存中已不存在的 id 忽略；列表为空或保存顺序为空时保持服务端顺序。
- 重排与恢复后，选中设备仍是同一台设备（按 id 重新定位索引）；设备列表为空时选中态为无效。
- 删除设备后同步更新保存的顺序。

## 设备备注

- 每台设备可写入本地备注，保存在 `device_note_<id>`；备注为空视为无备注。
- 列表项与当前设备卡片显示备注；写入后界面立即更新，重新进入页面后仍存在。

## 接水中守卫

- 正在接水时切换设备、进入或退出排序模式都不改变状态，并提示「正在接水中，请先结算」。
- 正在接水时主按钮执行结算；未选择设备时主按钮不可用，点击给出「请先选择设备」。

## 设备列表刷新

- 刷新去重：请求在途时再次触发刷新不并发发起第二个请求，且不会丢弃在途期间提出的重载要求——当前请求返回后补跑一次；登录过期分支不补跑。
- 下拉刷新与进入页面都会加载列表；加载失败时给出可重试提示并保留已有列表。
- 扫码添加成功后重新加载列表以显示新设备。

## 状态轮询与自动结算

- 开始接水成功后进入接水态并开始状态轮询；轮询沿用代际计数，控制器销毁或状态变更后迟到结果一律丢弃。
- 连续检测到设备空闲达到所需次数后自动结束接水态并停止轮询。
- 结算请求返回后立即取消轮询并退出接水态，再据返回结果决定提示内容。
- 状态查询异常时按「仍在使用」处理，避免网络抖动导致提前自动结算。

## 设备管理

- 支持扫码添加设备（含相机权限被拒时的说明）与删除设备，删除前确认。
- 添加与删除的结果以消息条反馈；同一设备的收藏请求在途时不重复发送。
